# حراسة لوحة التحكم بكلمة مرور واحدة على الخادم، لا بـ Supabase Auth

المحرّر واحد والمحتوى معلَن أصلاً، فلم نُنشئ مستخدمين في Supabase Auth. الحراسة كلمة مرور واحدة مخزّنة في متغيّر بيئة `ADMIN_PASSWORD` على Vercel: الواجهة ترسل ما كُتب، والخادم يقارن ويصدر كوكي `httpOnly` موقّعاً صالحاً ثلاثين يوماً. كلمة المرور لا تصل المتصفّح إطلاقاً، والواجهة لا تعرفها.

## أثر لاحق مهم

لا يوجد مستخدم مصادَق في Supabase، فسياسات RLS تمنح **القراءة للجميع ولا تمنح كتابةً لأحد**. كل عملية إنشاء أو تعديل تمرّ عبر Route Handler في Next.js يفحص الكوكي ثم يكتب بمفتاح `service_role`. أي أن لوحة التحكم لا تتحدّث مع Supabase من المتصفح مباشرةً — بخلاف منصة الطلاب.

## ما نقبله مقابل ذلك

لا يُعرف من عدّل ماذا (لا سجلّ تعديلات)، والمنصة معلّقة بمحرّر واحد. وإبطال الوصول عند تسرّب الكلمة يتم بتغيير المتغيّر في Vercel. الانتقال إلى حسابات مشرفين لاحقاً لا يهدم أي بيانات.
